## 2. 環境變數對照

本機只有根目錄一個 `.env`（從 `.env.example` 複製），網站與後台共用。部署到 Vercel 時，下面標「Vercel」的都要填到 Vercel 專案的 Environment Variables（Production 與 Preview）。

| 變數                                                               | 用途                                               | 去哪裡取得                                     | 放在哪裡                                   |
| ------------------------------------------------------------------ | -------------------------------------------------- | ---------------------------------------------- | ------------------------------------------ |
| `PUBLIC_SANITY_PROJECT_ID`                                         | 網站讀取 Sanity 內容                               | Sanity manage 專案首頁（`pg0x5cyw`，公開資訊） | .env、Vercel、GitHub CI（已寫在 workflow） |
| `PUBLIC_SANITY_DATASET`                                            | 同上                                               | 固定 `production`                              | .env、Vercel                               |
| `SANITY_API_READ_TOKEN`                                            | 讀草稿預覽（選用）                                 | Sanity manage → API → Tokens（Viewer 權限）    | .env、Vercel                               |
| `SANITY_STUDIO_PROJECT_ID`、`SANITY_STUDIO_DATASET`                | 後台連到哪個專案                                   | 同上                                           | .env（發布後台時使用）                     |
| `N8N_LEAD_WEBHOOK_URL`                                             | 網站把表單送給 n8n                                 | n8n 工作流的 Webhook 節點 → Production URL     | .env、Vercel                               |
| `N8N_LEAD_SECRET`                                                  | 網站與 n8n 之間的密鑰                              | 和 n8n 憑證「Aiii VBIM 官網表單密鑰」的值相同  | .env、Vercel、n8n 憑證                     |
| `PUBLIC_TURNSTILE_SITE_KEY`                                        | 表單防機器人（公開）                               | Cloudflare → Turnstile → Widget                | .env、Vercel                               |
| `TURNSTILE_SECRET_KEY`                                             | 表單防機器人（伺服器驗證）                         | 同上                                           | .env、Vercel                               |
| `CHECKLIST_FORM_BUILDING`／`_MANUFACTURING`／`_MEDICAL`／`_RETAIL` | 4 份需求表的 Google 表單預填網址（結尾 `LEAD_ID`） | `docs/需求表/google-forms-urls.md`（本機）     | .env、Vercel                               |
| `CHECKLIST_PDF_BUILDING`／…                                        | 需求表 PDF 的雲端硬碟連結（只附在確認信）          | Google 雲端硬碟「知道連結的人可檢視」          | .env、Vercel                               |
| `PUBLIC_GA_ID`                                                     | Google Analytics 4（選用，留空不載入）             | GA4 → 管理 → 資料串流                          | .env、Vercel                               |

> 本機開發時，`.env` 目前用的是 **Cloudflare 官方測試金鑰**（一定通過驗證）。正式環境一定要換成自己申請的金鑰。

## 3. 各服務之間怎麼串

```
訪客填表 ─→ 官網 /api/lead（Vercel）
             ├ 驗證欄位、Turnstile、防灌單
             └ POST（帶 X-Lead-Secret）─→ n8n 工作流
                                         ├ 寫入 Google 試算表「Aiii VBIM 官網名單」
                                         ├ 回應官網成功／失敗
                                         ├ Gmail 寄確認信給填表人（業主附需求表連結）
                                         └ Gmail 寄內部通知（收件人與副本設定在 n8n 節點）

業主在後台發布 ─→ Sanity Webhook ─→ Vercel Deploy Hook ─→ 官網重新建置（約 3 分鐘內更新）
                  （上線時設定；Deploy Hook 網址只放在 Sanity Webhook 設定裡）
```

## 4. 常見設定操作

### 4-1 新增可以登入後台的成員

Sanity manage → 專案 `pg0x5cyw` → **Members** → Invite → 輸入對方 Email → 角色選 **Administrator**（可編輯）或 **Viewer**（只能看）。
免費方案只有這兩種角色；「只能存草稿、不能發布」用後台的「待審稿」機制處理（見 `SOP-後台操作手冊.md`）。

### 4-2 重新發布後台（後台程式有更新時）

```bash
npm run studio:deploy
```

撤下後台：在 `apps/studio` 資料夾執行 `npx sanity undeploy`（只移除後台網頁，內容資料不受影響）。

### 4-3 更換表單通知收件人

n8n → 工作流「Aiii VBIM 官網｜表單名單（webhook）」→ 節點「內部通知信」→ To／CC。不要寫進程式碼或這份文件。

### 4-4 更換需求表題目

需求表內容由 Andy 設計（`docs/需求表/`，不上傳）。Google 表單可直接在 Google 表單編輯畫面修改；若重新用 `docs/需求表/google-forms.gs` 產生新表單，要把新的預填網址更新到 `.env` 與 Vercel 的 `CHECKLIST_FORM_*`。

### 4-5 更換 Turnstile 金鑰

Cloudflare 建立新的 Widget（主機名稱 `aiiivbim.com`、`www.aiiivbim.com`、本機測試加 `localhost`）→ 把 Site Key、Secret Key 更新到 `.env` 與 Vercel → Vercel 重新部署。
