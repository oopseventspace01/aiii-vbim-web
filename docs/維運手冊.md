## 2. 每月檢查（約 30 分鐘）

- [ ] **網站速度**：用 [PageSpeed Insights](https://pagespeed.web.dev/) 測首頁與平台頁的手機版，效能 ≥ 90、無障礙 ≥ 95、SEO ≥ 95（SPEC 8）。
- [ ] **Google 收錄**：Google Search Console → 「網頁」報告，看有沒有大量「未編入索引」或錯誤。
- [ ] **內容檢查**：後台新增了不少內容的話，請工程師在本機跑 `npm run build` 與 `npm run check:content -w apps/web`，確認沒有禁用名稱、`[TBD]` 等佔位文字。
- [ ] **額度**：
  - LINE 官方帳號（推播上線後）：Official Account Manager → 用量，看當月推播則數有沒有接近免費上限。
  - Gmail：每日寄送有上限；名單量變大時改用公司網域信箱寄信。
  - Vercel：Usage 頁面看流量與建置次數。
  - Sanity：manage → Usage，看 API 請求與資料量。
- [ ] **套件與資安**：GitHub → Security（Dependabot 提醒），有重大更新請工程師處理。

## 3. 常見問題

### 3-1 後台發布了，網站沒有更新

1. 等 3 分鐘再重新整理（瀏覽器按 Ctrl＋F5 強制重新整理）。
2. 確認文件真的「已發布」：後台文件右下角顯示 Published，不是 Draft；有「待審稿」勾選就發布不了。
3. 「發布時間」設成未來的消息，要等到時間過後的下一次重建才會出現。
4. Vercel → Deployments，看最新一次部署是不是失敗（紅色）。失敗的話點進去看 Logs，或按「Redeploy」重試。
5. Sanity manage → API → Webhooks，確認通往 Vercel Deploy Hook 的 Webhook 還在、最近有成功紀錄。

### 3-2 表單送出顯示「目前無法送出」

這代表網站沒有把名單存成功（網站不會假裝成功）。依序檢查：

1. n8n 是否在運作：打開 n8n 後台能登入嗎？工作流是 **Active** 嗎？
2. n8n → Executions：最新一筆失敗在哪個節點。
   - 「寫入名單試算表」失敗：Google 憑證過期 → n8n Credentials 重新登入 Google；或試算表被改名、分頁被改名（分頁名稱要是 `Untitled`，或同步修改節點設定）。
   - 沒有任何紀錄：網站的 `N8N_LEAD_WEBHOOK_URL`、`N8N_LEAD_SECRET` 與 n8n 不一致，或 Webhook 路徑被改過。
3. Turnstile 金鑰過期或網域沒加到 Widget：訪客會看到「請先完成驗證後再送出」。

### 3-3 試算表有名單，但填表人說沒收到確認信

- 請對方看垃圾信匣。
- n8n → Executions → 該筆的「確認信給填表人」節點有沒有錯誤（Gmail 憑證過期、超過每日上限）。
- 補寄：從試算表找到對方 Email 與預約編號，手動回信。

### 3-4 想查某個預約編號

- 試算表搜尋（Ctrl＋F）預約編號，例如 `L-261028-GJBF`。
- 業主若填了需求表，Google 表單的回覆試算表裡也會有同一個預約編號。

### 3-5 有人在網站看到錯字或錯的資訊

- 內容（消息、案例、首頁標語、公司資訊）：後台直接改，見 `SOP-後台操作手冊.md`。
- 固定頁面的文案（平台、五大領域等設計稿文字）：寫在程式裡，請工程師修改（`apps/web/src/content/pages/`）。

### 3-6 網站整個打不開

1. 先看 Vercel → Deployments 最新部署狀態；有問題就把上一個正常版本「Promote to Production」（見 `rollback-plan.md`）。
2. 若是網域問題（DNS），見 `launch-checklist.md` 第 4 節。
