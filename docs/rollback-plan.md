# 回滾計畫（SPEC 13-4）

出問題時，依「壞掉的是哪一層」選對應的回復方法。原則：**先恢復服務，再查原因**。

| 狀況                               | 用哪一節 | 大約多久恢復                   |
| ---------------------------------- | -------- | ------------------------------ |
| 新版網站有錯（頁面壞掉、樣式跑掉） | 1. 程式  | 幾秒                           |
| 後台內容被改錯或刪掉               | 2. 內容  | 幾分鐘                         |
| 換網域後網站或信箱不正常           | 3. 網域  | 視 DNS 生效時間，通常 1 小時內 |
| 表單收不到名單                     | 4. 表單  | 網站自動保護；修好 n8n 即恢復  |

---

## 1. 程式（Vercel）

**方法 A：Instant Rollback（最快，不用改程式）**

1. Vercel → 專案 → **Deployments**
2. 找到上一個正常的部署（綠色 Ready）→ 右側「⋯」→ **Promote to Production**（或 Instant Rollback）
3. 幾秒內正式網站就換回那個版本。

**方法 B：git revert（要把錯的修改永久拿掉時）**

```bash
git revert <有問題的 commit 編號>
```

```bash
git push
```

推上去後 Vercel 會自動重新部署。commit 編號在 GitHub 的 Commits 頁面可以找到。

> 注意：方法 A 之後，下一次有人 push 或後台發布觸發重建，又會部署最新的程式。所以 A 是急救，之後還是要用 B 或修正程式。

---

## 2. 內容（Sanity）

**單一文件改錯**：後台打開該文件 → 右上角「⋯」→ **History** → 選之前的版本 → **Restore** → **Publish**。

**文件被刪除**：Sanity 文件歷史在刪除後仍保留一段時間（依方案）。從 manage 或請工程師用 API 依文件 ID 還原；若有月備份，也可以從備份還原：

```bash
npx sanity dataset import backup.tar.gz production --replace
```

（在 `apps/studio` 資料夾執行；`--replace` 會覆蓋同 ID 的文件，執行前請先再匯出一次目前的資料當保險。這是影響正式資料的動作，請工程師確認後執行。）

**不想讓某篇內容出現**：不用刪，按「Unpublish」即可。

還原或修改後，網站會在重建後（約 3 分鐘內）更新。

---

## 3. 網域（DNS）

完整步驟與舊網站的 DNS 值在 `launch-checklist.md` 第 0、4 節。重點：

1. Namecheap → Advanced DNS：把 `A @` 改回舊網站（Gamma）的兩個 IP、`CNAME www` 改回 `sites.gamma.app`。
2. **不要動 MX、TXT**（公司信箱與 Google 驗證）。
3. **TTL 注意事項**：DNS 改了之後，各地網路會依 TTL（快取時間）慢慢更新。目前紀錄的 TTL 約 30 分鐘（1800 秒），所以改回去後大約 30 分鐘到 1 小時才會全部生效；有些網路可能更久。
   - 建議：**切換前一天**先把要改的紀錄 TTL 調成 5 分鐘（300 秒），萬一要回滾就能很快生效；穩定一週後再調回來。
4. 切換期間**不要刪除 Gamma 上的舊網站**，回滾才有地方可以指回去。

---

## 4. 表單（n8n）

- n8n 停擺、Webhook 錯誤、試算表寫不進去時，網站的 `/api/lead` 會回傳錯誤，畫面顯示「目前無法送出，請稍後再試，或直接來信：（公司 Email）」，**不會讓訪客以為已送出**。
- 恢復方法：見 `維運手冊.md` 3-2。修好後不需要動網站。
- 若要暫時改由人工收件：在後台「全站設定」確認公司 Email 正確即可（錯誤訊息會顯示這個 Email）。

---

## 5. 後台網頁（Sanity Studio）

- 後台程式更新後有問題：用上一版程式重新發布即可：
  ```bash
  git checkout <上一版 commit> -- apps/studio
  ```
  ```bash
  npm run studio:deploy
  ```
  發布完成後，再用 `git checkout main -- apps/studio` 回到最新程式並修正。
- 後台網頁出問題不影響官網，也不影響內容資料。
